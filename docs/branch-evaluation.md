# Branch display evaluation (not implemented)

Crossroads currently obtains pane/workspace ordering and names from an initial snapshot (`src/main.rs:192-276`) and looks up `herdr worktree list --workspace <ID>` once per uncovered workspace (`src/main.rs:279-373`). It annotates **linked** open workspaces with `↳ <label> (<branch>)` when a nonempty branch is present, and groups those workspaces under the source workspace only when `source.source_workspace_id` is present, the source workspace is displayed in the snapshot, and its ID differs from the linked workspace ID. Ordinary workspaces keep their snapshot label; no ordinary branch is displayed. Failed/invalid worktree lookups leave plain labels. This is covered by `tests/startup.rs` (`startup_marks_only_linked_workspace_by_id_and_does_not_requery_on_search`, `failed_or_invalid_worktree_lookup_falls_back_to_plain_workspace_names`). Status events do not refresh branch metadata; when `HERDR_SOCKET_PATH` is set, a status-socket reconnection re-subscribes and re-snapshots in the background (`src/main.rs:1759-1818`). Without a socket path, only the initial snapshot runs (`src/main.rs:1652-1660`, `src/main.rs:1795-1799`).

## Options for a future decision

| Option | Ordinary workspace | Linked workspace | Freshness / cost |
| --- | --- | --- | --- |
| Keep current behavior | Snapshot label only | Existing branch annotation where reported | Lookup at startup and on status-socket reconnection, one call per uncovered workspace per snapshot; no branch refresh on ordinary status events. |
| Annotate both, using existing `worktree list --workspace` | Add an ordinary branch suffix only if the response identifies an open ordinary checkout | Keep existing annotation | No extra class of CLI call, but broader parsing/UI changes and stale until the next explicit metadata refresh. Need a policy for branch missing/detached; do not infer `main`. |
| Wide-only branch column | Explicit branch column for both when there is room | Same column, retain or reconsider link marker | Requires responsive-width and clipping design, changes wide-only layout and tests; same metadata freshness unless separately refreshed. Narrow layouts still need a fallback. |

Herdr v0.9.1 `worktree list --workspace ID` is supported by its CLI; the wire `worktree_list` result contains `source` and `worktrees`. Each worktree has optional `branch` and `open_workspace_id`, and boolean `is_linked_worktree`, `is_detached`, and `is_prunable` fields; `source_workspace_id` is optional. See [v0.9.1 CLI](https://github.com/herdrdev/herdr/blob/v0.9.1/src/cli/worktree.rs), [worktree schema](https://github.com/herdrdev/herdr/blob/v0.9.1/src/api/schema/worktrees.rs), and [response schema](https://github.com/herdrdev/herdr/blob/v0.9.1/src/api/schema/response.rs). An absent source ID means grouping cannot be established from the result; a missing/empty branch or detached checkout should not be labeled as a named branch. `is_prunable` or no `open_workspace_id` is not proof of a visible live workspace. Repeated metadata queries may cost startup time; per-key CLI calls would be inappropriate. A refresh policy would need separate approval and tests for stale/removed/renamed branches and unavailable repositories.

**No branch-display implementation is approved here.** The ordinary-workspace display choice, detached wording, fallback on unavailable metadata, wide/narrow presentation, and desired freshness remain product decisions.
