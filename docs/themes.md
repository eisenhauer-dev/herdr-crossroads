# Themes

See the [README](../README.md#configuration-and-complete-defaults-overview) for
setup/defaults and [architecture](architecture.md#themes-and-persistence) for the
theme-state and persistence flow.

By default, in Select mode press `t` to replace the pane table with a scrollable theme list. In Search mode, `t` is ordinary search text. Use `j`/`k` or ↑/↓ to change the theme cursor, then press Space to toggle between the list and a live pane-table preview before saving. In either view, those keys change only the theme cursor, not the pane selection or search filter. The preview uses the current filtered panes and query, with themed selection, search matches, and visible status colors; its header shows the saved and previewed theme. Enter saves and returns to the pane list; Esc or q cancels and restores the previous theme. The picker keeps the pane selection, search query, and filtered rows unchanged. These are the default bindings: [keymaps](keymaps.md) can replace `select.open_themes` and the six `themes` actions, including `open_help`, with one or two keys each. Both views show the first effective key per displayed footer action, plus configured arrows for navigation, with directed action groups. Each footer action unit wraps intact; footers reserve up to three rows as needed, separately from any notice. Defaults remain fully visible without paging at 80×15 and wider sizes. Only oversized custom footers page automatically every two seconds.

In either Themes view, `?` opens `Keys — Themes` with only the effective Themes
actions and bindings. Help uses the pending preview palette and its own search;
default Esc or q returns to the same list/table preview, theme cursor and saved
choice without saving, canceling or focusing a pane. Pane query, selection and
viewport remain untouched. Esc during help search first ends editing, then a
second Esc returns to Themes. In pane/help search, `?` is ordinary text.
Theme navigation wraps in both directions: previous from Auto selects `vesper`,
and next from `vesper` selects Auto, in both list and table preview. The palette
changes immediately, but neither navigation nor preview toggling writes a theme
file. Help cycles only through matching entries, without changing its query.
The table preview's search row has a right-aligned `Themes` mode label; help's
search row shows `Help`, separately from `Keys — Themes`. The theme list has no
search row and keeps its existing `Themes · selected: … · preview: …` heading.

The picker offers Auto (Herdr) plus Herdr v0.9.1's 18 built-ins: `catppuccin`, `catppuccin-latte`, `terminal`, `tokyo-night`, `tokyo-night-day`, `dracula`, `nord`, `gruvbox`, `gruvbox-light`, `one-dark`, `one-light`, `solarized`, `solarized-light`, `kanagawa`, `kanagawa-lotus`, `rose-pine`, `rose-pine-dawn`, and `vesper`. `terminal` uses terminal default foreground and background and ANSI palette colors, not a fixed RGB approximation.

In the interactive popup, every non-terminal theme, including Catppuccin Mocha, paints the full frame with its Herdr v0.9.1 panel background and text color, including the theme list, table preview, blank rows, and space beyond the text. Mocha uses panel background `#181825` and text `#cdd6f4`. Selected rows retain their own highlight; following rows return to the theme background. Only `terminal` inherits the current terminal's default foreground and background (with reverse-video selection), whatever those defaults are. Non-interactive output remains plain text without ANSI styling.

All ERROR and INFO notice text replaces control characters with spaces before
clipping and renderer styling, including decoded escapes in theme names or unknown
JSON field names and failed-save messages. Such text cannot inject terminal
commands or extra notice rows; the renderer's own color and bold styling is retained.

At opening, Crossroads reads `theme.jsonc` once under `HERDR_PLUGIN_CONFIG_DIR`, or legacy `theme.json` **only if `.jsonc` is absent**. Both accept JSON plus `//` and `/* … */` comments and object/array trailing commas, but not other JSON5 syntax or duplicate fields. The schema is exactly one `theme` field naming an offered explicit theme, for example `{"theme":"dracula"}`. Missing files select Auto; there is no startup migration, write, or deletion. An existing invalid or unreadable `.jsonc` is never replaced by a legacy `.json` fallback.

Crossroads saves an explicit choice as a minimal `theme.jsonc`, without preserving comments. It writes and syncs a temporary file in the same directory and atomically renames it into place only after writing succeeds, so a failed replacement does not truncate the previous `.jsonc` choice. A legacy `theme.json` is left untouched by explicit saves. Explicitly saving Auto attempts to remove **both** `theme.jsonc` and `theme.json`; deletion failure is reported, even if one file was already removed. It does not pretend the switch succeeded: the picker stays open and the saved in-memory choice is unchanged. Saving keeps the previewed theme in the current popup and loads it again on later openings; unsaved previews affect only the current popup. Crossroads does **not** change Herdr's own config, theme, or terminal colors. A failed save/delete leaves the picker open with a bold, warning-colored `ERROR` notice on its own line above the key help; invalid or unreadable theme files remain untouched, use Mocha, and show the same kind of notice until the next key. Notices start with `ERROR` and omit configuration file names and paths. The notice never replaces the effective navigation or save/cancel help, including at 80×15; long notices may be clipped.

Theme errors alone retain the normal UI with Mocha fallback and pathless notices. When startup also detects keymap or status-color errors, all recoverable theme diagnostics appear on the [common configuration error page](keymaps.md#conflicts-and-error-page). Each error kind has its own bold, error-colored `ERROR:` heading, then one source row, then a simple diagnostic list. The source row shows the filename in normal text, two spaces, and the full selected file path in the active theme's dim color. The source is `.jsonc` when present, otherwise legacy `.json`, including for IO/syntax errors; diagnostic lines never repeat it. Source rows never wrap: long paths clip on the right with `…` using Unicode cell widths, preserving the filename where possible. Extremely narrow rows omit the path or clip the filename safely. Plain-text output has the same single clipped row without styling. The source row scrolls with its block. Horizontal separators divide blocks. Content scrolls independently above the fixed bottom navigation footer and full-width separator at three or more rows; one or two rows prioritize diagnostics with ERROR markers and omit headings/source rows. Interactive content below 80×15 adds a first `ERROR: Popup too small` block with required/actual dimensions and enlarge/reopen advice, alongside all configuration errors but no configuration path; resize updates or removes it without discarding theme diagnostics. Noninteractive output has no such size block. Duplicate occurrences and other reliably detectable field errors are collected together; an unreadable or unparseable file contributes only IO or syntax diagnostics, not invented field errors.

Auto reads `HERDR_CONFIG_PATH`, or `XDG_CONFIG_HOME/herdr/config.toml`, or `HOME/.config/herdr/config.toml` (in that order). It recognizes only a single literal `name = "…"` inside `[theme]`, with absent or false `auto_switch` and no additional theme settings or custom sections. Known themes must match the 18 built-in names exactly; `Auto (Herdr)` is only a Crossroads picker entry, not a Herdr theme name. It accepts only simple bare table headers and scalar assignments elsewhere (such as `[ui]` with `foo = 1`); malformed or unsupported syntax falls back to Mocha. This is a conservative choice recognizer, not full TOML validation. A single literal manual name outside the 18 offered themes (for example `catppuccin-mocha` or `Auto (Herdr)`) uses Mocha and shows a subtler, dim-colored `INFO` line above the retained key help until the next key, at startup when Auto is selected and when the picker opens on or moves to Auto. Redrawing does not repeat the notice; a later Auto transition can show it again. This notice does not modify either theme file and is distinct from the `ERROR` notice for an unknown name *in* `theme.jsonc` or legacy `theme.json`. When the Herdr file is missing, unreadable, ambiguous, has unsupported syntax, uses a custom override, or SSH environment variables are present, Auto uses Mocha without this notice. It does not follow live auto-switching or custom Herdr tokens. See [status colors](status-colors.md) for precedence of the separate status overrides.
