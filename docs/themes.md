# Themes

In Select mode, press `t` to replace the pane table with a scrollable theme list. In Search mode, `t` is ordinary search text. Use `j`/`k` or Up/Down to change the theme cursor, then press Space to toggle between the list and a live pane-table preview before saving. In either view, those keys change only the theme cursor, not the pane selection or search filter. The preview uses the current filtered panes and query, with themed selection, search matches, and visible status colors; its header shows the saved and previewed theme. Enter saves and returns to the pane list; Esc cancels and restores the previous theme. The picker keeps the pane selection, search query, and filtered rows unchanged. Both views show Space, Enter, and Esc help at 80×15 and wider sizes.

The picker offers Auto (Herdr) plus Herdr v0.9.1's 18 built-ins: `catppuccin`, `catppuccin-latte`, `terminal`, `tokyo-night`, `tokyo-night-day`, `dracula`, `nord`, `gruvbox`, `gruvbox-light`, `one-dark`, `one-light`, `solarized`, `solarized-light`, `kanagawa`, `kanagawa-lotus`, `rose-pine`, `rose-pine-dawn`, and `vesper`. `terminal` uses terminal default foreground and background and ANSI palette colors, not a fixed RGB approximation.

In the interactive popup, every non-terminal theme, including Catppuccin Mocha, paints the full frame with its Herdr v0.9.1 panel background and text color, including the theme list, table preview, blank rows, and space beyond the text. Mocha uses panel background `#181825` and text `#cdd6f4`. Selected rows retain their own highlight; following rows return to the theme background. Only `terminal` inherits the current terminal's default foreground and background (with reverse-video selection), whatever those defaults are. Non-interactive output remains plain text without ANSI styling.

Crossroads saves an explicit choice in `theme.json` under `HERDR_PLUGIN_CONFIG_DIR`, for example `{"theme":"dracula"}`. It writes a temporary file in the same directory and renames it into place only after writing succeeds, so a failed write does not truncate the previous choice. Auto removes `theme.json` directly. Saving keeps the previewed theme in the current popup and loads it again on later openings; unsaved previews affect only the current popup. Crossroads does **not** change Herdr's own config, theme, or terminal colors. A failed save/delete leaves the picker open with a bold, warning-colored `ERROR` notice on its own line above the key help; invalid or unreadable `theme.json` leaves the file untouched, uses Mocha, and shows the same kind of notice until the next key. The notice never replaces the navigation or save/cancel help, including at 80×15.

Auto reads `HERDR_CONFIG_PATH`, or `XDG_CONFIG_HOME/herdr/config.toml`, or `HOME/.config/herdr/config.toml` (in that order). It recognizes only a single literal `name = "…"` inside `[theme]`, with absent or false `auto_switch` and no additional theme settings or custom sections. Known themes must match the 18 built-in names exactly; `Auto (Herdr)` is only a Crossroads picker entry, not a Herdr theme name. It accepts only simple bare table headers and scalar assignments elsewhere (such as `[ui]` with `foo = 1`); malformed or unsupported syntax falls back to Mocha. This is a conservative choice recognizer, not full TOML validation. A single literal manual name outside the 18 offered themes (for example `catppuccin-mocha` or `Auto (Herdr)`) uses Mocha and shows a subtler, dim-colored `INFO` line above the retained key help until the next key, at startup when Auto is selected and when the picker opens on or moves to Auto. Redrawing does not repeat the notice; a later Auto transition can show it again. This notice does not modify `theme.json` and is distinct from the `ERROR` notice for an unknown name *in* `theme.json`. When the Herdr file is missing, unreadable, ambiguous, has unsupported syntax, uses a custom override, or SSH environment variables are present, Auto uses Mocha without this notice. It does not follow live auto-switching or custom Herdr tokens. See [status colors](status-colors.md) for precedence of the separate status overrides.
